## P0 — 必须解决（影响可玩性）

### 1. AI 战术层（最大缺口）
- **现状**: `ai/local.py` 仅137行，只有战略层（attack-move），无战术智能
- **缺失**: 侧翼包抄、撤退/残血管理、侦察行为、刺杀目标选择、工兵多样性（只造桥不造船/塔/路）、体力/冲锋使用
- **文件**: `src/mygame/ai/local.py`
- **方案**: 添加战术层，每0.2-0.5s决策：近战接敌优化、残血单位后撤、侦察兵独立侦察路径、刺客绕后突袭将领、工兵根据地形造船/建塔

### 2. AI 工程多样性
- **现状**: AI 只会架桥，从不造船、修路、建塔
- **文件**: `src/mygame/ai/local.py`
- **方案**: 根据河流位置决定造船，根据森林密度决定修路，防守时建塔

### 3. AI 难度设置
- **现状**: 配置有 `ai["normal"]` 但 UI 只显示静态文字，无法切换
- **文件**: `src/mygame/ai/local.py`, `src/mygame/app/game.py` (setup 界面)
- **方案**: 至少支持 easy/normal/hard，调整决策间隔、任务上限、攻击性

### 4. 战斗统计/结算画面
- **现状**: 结算画面只显示双方损失总数
- **文件**: `src/mygame/app/game.py` (`_draw_result`)
- **方案**: 按兵种分类的击杀/损失/伤害统计、游戏时长、命令数

### 5. 指令书（F1）完善
- **现状**: F1 打开简单帮助覆盖层，内容有限
- **文件**: `src/mygame/app/game.py` (`_draw_help`)
- **方案**: 列出所有支持的命令、兵种名称、示例句子，参照 README 中的命令列表

## P1 — 高优先级（影响体验）

### 6. 地形渲染性能优化
- **现状**: `_draw_terrain` 逐瓦片调用 `pygame.draw.rect`，每帧约9000次绘制调用
- **文件**: `src/mygame/app/game.py` (line ~1303-1320)
- **方案**: 预渲染地形到 Surface（类似 minimap 的 numpy 方法），只在相机移动显著时重建

### 7. 小地图每帧重建优化
- **现状**: `_draw_minimap` 每帧创建新 numpy 数组 + `make_surface` + 1000次 `set_at`
- **文件**: `src/mygame/app/game.py` (line ~1596-1650)
- **方案**: 缓存地形 Surface，只更新单位点

### 8. 窗口失焦时语音录制卡住
- **现状**: 按住 V 开始录制，窗口失焦时 KEYUP 不会触发，`self.recording` 永远为 True
- **文件**: `src/mygame/app/game.py` (line ~432-479)
- **方案**: 添加 `WINDOWFOCUSLOST` 事件处理，失焦时自动停止录制

### 9. `reduced_motion` 设置未生效
- **现状**: 设置存储了 `reduced_motion` 但渲染代码从未检查此标志
- **文件**: `src/mygame/app/game.py` (所有 draw 方法)
- **方案**: 在动画/过渡效果中检查此标志，为 True 时跳过动画

### 10. 菜单无键盘导航
- **现状**: 菜单只响应鼠标点击，无法用 Tab/Enter 导航
- **文件**: `src/mygame/app/game.py` (`_menu_event`)
- **方案**: 添加 Tab 切换焦点、Enter 确认、方向键导航

### 11. Windows DPI 感知
- **现状**: 未调用 `SetProcessDPIAware()`，高 DPI 显示器上窗口模糊
- **文件**: `src/mygame/app/game.py` (初始化)
- **方案**: 在 pygame.init 之前调用 ctypes 设置 DPI 感知

### 12. 手工制作默认地图
- **现状**: 只有程序化生成，设计计划要求"一个高质量严格对称地图"
- **文件**: `src/mygame/maps/model.py`
- **方案**: 添加一个精心设计的默认地图，作为 setup 界面的默认选项

## P2 — 中优先级（代码质量）

### 13. GameApp 拆分（God Object）
- **现状**: `game.py` 1890行，一个类处理所有逻辑：事件、场景、输入、AI、渲染、HUD、相机、音效、设置
- **文件**: `src/mygame/app/game.py`
- **方案**: 拆分为 `MenuScene`, `BattleScene`, `ReplayScene` 等场景类，`GameApp` 管理场景切换和共享资源

### 14. 战斗系统 Python 循环优化
- **现状**: `_resolve_combat` 中 `for attacker in attackers:` 是纯 Python 循环，每4 tick 对所有活跃单位执行
- **文件**: `src/mygame/simulation/world.py` (line ~1267)
- **方案**: 将空间桶预计算为 numpy 数组，使用向量化距离计算选择目标

### 15. `_resolve_combat` 方法过长
- **现状**: 180+ 行，处理空间分桶、目标选择、守卫拦截、设施攻击、伤害累积、死亡判定
- **文件**: `src/mygame/simulation/world.py` (line ~1216-1409)
- **方案**: 拆分为 `_select_targets`, `_apply_damage`, `_handle_guard_intercept` 等子方法

### 16. 补充测试覆盖
- **现状**: 38个测试，GameApp 零覆盖，命令解析器只有5个测试，无 AI 行为测试
- **文件**: `tests/`
- **方案**:
  - 为 README 中列出的每种命令模式添加解析器测试
  - 添加 AI 信息隔离测试（验证 AI 无法访问隐藏单位）
  - 添加碰撞/战斗/船只/河流伤害测试
  - 添加 500v500 含战斗的性能基准测试

### 17. 静默异常吞没
- **现状**: 多处 bare `except: pass`，包括音效加载、回放保存、设置保存
- **文件**: `src/mygame/app/game.py` (line ~113, 779, 1239)
- **方案**: 至少记录日志 `logging.warning`

### 18. RuleCommandParser 世界尺寸未更新
- **现状**: parser 在 `__init__` 中以默认 4096x2304 创建，`new_battle` 不更新尺寸
- **文件**: `src/mygame/app/game.py` (line ~181), `src/mygame/commands/parser.py`
- **方案**: 在 `new_battle` 中更新 `self.rule_parser.world_width/height`
